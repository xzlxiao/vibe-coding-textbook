## 1. 项目是什么

`csvkit` 是一个只做一件事的库：把内存里的记录写成 CSV，并保证列顺序是对外契约。
不处理数据库、不处理鉴权、不做 HTTP 服务。

## 2. 技术栈（改动需在 PR 说明理由）

- Python 3.11+，无第三方运行时依赖（只用标准库 `csv`）
- 开发依赖：ruff、mypy（strict）、pytest
- 包管理：pip + `pyproject.toml`；**不引入** poetry / uv / conda

## 3. 目录职责

| 路径 | 职责 | 禁止 |
|---|---|---|
| `src/csvkit/` | 业务实现 | 出现 `print`、`sys.exit`、网络 IO |
| `tests/` | 行为契约 | 断言私有函数、断言日志文本 |
| `scripts/` | 开发辅助 | 被 `src/` 导入 |

## 4. 命令（改完必须自己跑一遍）

```bash
ruff check .            # lint
mypy src                # 类型
pytest -q               # 单测
```

**完成定义（Definition of Done）**：上面三条全绿 + 新增行为有对应测试。
三条里任何一条没跑，任务就不算完成，不要用"应该没问题"作为结论。

## 5. 硬性约定

- 公开函数的参数与返回值**必须**有类型标注；`Any` 需要注释说明来源。
- CSV 列顺序写在 `COLUMNS` 常量里，改动必须同步改 `README` 与 `tests/test_export.py`。
- 异常只抛 `ValueError`（输入非法）或 `OSError`（IO 失败）；不自造异常体系。
- **禁止**新增依赖，除非在 PR 里写清"为什么标准库不够"。

## 6. 禁区（这些事不要做，做了会被门禁拦下）

- 不要为了让测试变绿而修改测试的期望值。先判断是测试错还是实现错，并在回复里说明判据。
- 不要吞异常（`except Exception: pass`）。要么处理，要么让它冒出去。
- 不要在 `src/` 里读环境变量做配置；配置由调用方传入。
- 不要生成 `requirements.txt`；依赖只有一个来源：`pyproject.toml`。
