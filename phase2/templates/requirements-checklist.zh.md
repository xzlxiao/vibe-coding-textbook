# 需求质量清单

> 用法：这是"用自然语言写的单元测试"（第 08 章）。
> **由评审者勾选，实现者只能提交待审。** 全绿但上线出问题，说明清单本身需要加一条。
> 每条只能答"是 / 否"。答"否"就回上游，不要在这里解释。

## A. 判据质量

- [ ] A1 每条判据都有可观测的出口（接口字段 / 页面元素 / 数据状态 / 日志）
- [ ] A2 每条判据都有量化值或枚举，没有形容词
- [ ] A3 每条核心判据都配了失败路径（IF ... THEN）
- [ ] A4 全篇只用"应 / 不得"，没有"宜 / 可"
- [ ] A5 一条判据只描述一个行为

## B. 覆盖度

- [ ] B1 六类歧义（指代 / 范围 / 边界 / 例外 / 时序并发 / 权限可见）都扫过
- [ ] B2 六类约束（幂等 / 并发 / 超时重试 / 权限 / 性能 / 降级）都有条款或"不适用 + 理由"
- [ ] B3 Non-goals 至少三条，且都是可判定的缺失
- [ ] B4 边界值都写明了（0、1、上限、上限 + 1、同值、超时）

## C. 分层与一致性

- [ ] C1 spec 里没有框架名 / 表名 / 函数名 / 目录结构
- [ ] C2 plan 里没有出现新需求
- [ ] C3 每条任务都有"怎么算过"
- [ ] C4 任务依赖没有环
- [ ] C5 每条判据都被至少一个任务覆盖（无孤儿需求）
- [ ] C6 没有两处对同一概念的不同定义（例如"满员"出现两种口径）
- [ ] C7 没有"待定"被悄悄按默认值执行（若有，已记入待确认决策表）
